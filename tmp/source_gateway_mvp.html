NS100 Agent / Data Access First Step

第一阶段先做 Source Gateway，而不是先做大爬虫或完整 Agent。

这版设计把 6 类数据源统一成可审计入口：强证据、市场上下文、搜索线索和弱信号分开建模。 后续数据挖掘、知识图谱和 Agent 工具都复用同一套 typed schema。

推荐结论

数据层第一阶段用 Python，TS 留给前端和配置台。

原因很朴素：SEC、YFinance、OpenBB、文本抽取、Pydantic schema、后续聚类/embedding/证据抽取， Python 生态更短路。TypeScript 可以等到有 Web UI、管理台、用户配置和 brief 页面时再上。

MVP 范围

先跑 3-5 个 ticker。

例如 NVDA、MSFT、AAPL、AMZN、GOOGL。 每次抓取生成 raw 文件、normalized JSONL 和 run manifest。

Strong Evidence

SEC EDGAR

8-K、10-Q、10-K、Form 4、13D/G 等。第一优先级，适合进入 Document 和 Evidence。

Strong Evidence

公司 IR / Press Release

IR RSS、earnings release、presentation、公司新闻稿。先覆盖核心 watchlist，不做全网爬。

Market Context

YFinance / OpenBB-yfinance

价格、成交量、相对 QQQ/XLK/SOXX 的反应。它证明市场反应，不证明事件原因。

Search Lead

Tavily

给 Agent/RAG 找线索。搜索结果只能是 lead，需要回到原文或强证据源确认。

Search Lead

Brave Search

独立 web index，作为 Tavily 的补充，减少单一搜索源偏差。

Weak Signal

Stock Sentiment API

Reddit / X / Polymarket 热度和情绪。只做 attention signal，不作为事实证据。

第一阶段数据流

Source Registry 登记 source_id、tier、family、license、rate limit、allowed_use。
Adapter Fetch 每个来源一个 adapter：list、fetch、search、read。
Raw Store 保存原始 JSON、RSS item、HTML、响应 metadata 和 hash。
Normalize 统一成 Document、MarketContext、SearchLead、AttentionSignal。
Manifest 记录本次 run 的成功、失败、数量、耗时和错误原因。
Next Layer 喂给 dedup、event seed、claim/evidence、KG 和 Agent tools。

Python vs TypeScript：数据层选型

Python 数据层

  • 更适合 SEC、YFinance、OpenBB、文本抽取、时间序列和后续 ML/RAG。
  • Pydantic 可以直接承载 Document、Event、Claim、Evidence schema。
  • 2-3 天 MVP 更容易跑通：CLI + JSONL + pytest。
  • 后面接 FastAPI、Dagster、pgvector、LangGraph 都顺。

TypeScript 数据层

  • 适合 Web UI、用户配置、管理台、brief 页面和 API client。
  • 端到端类型体验好，但金融/文本/爬取生态没有 Python 省力。
  • 如果第一阶段全用 TS，会在 SEC、行情、清洗、抽取上绕远。
  • 建议用来消费 Python API，而不是承载 ingestion core。
层 第一阶段技术 后续演进
数据接入核心 Python package + Pydantic + httpx FastAPI service / MCP wrapper
存储 raw files + normalized JSONL + manifest Postgres + pgvector + object storage
搜索线索 Tavily + Brave adapters 统一 SearchLead index，Agent 受控调用
行情上下文 YFinance 或 OpenBB-yfinance Longbridge / TickFlow / 授权商业行情源
前端 暂时不用，先静态 HTML/CLI 输出 Next.js + TypeScript
推荐第一步：只实现 Source Registry、6 个 adapter skeleton、统一 schema、JSONL 输出和 run manifest。 先别做知识图谱、LangGraph、多 Agent、复杂数据库。这个项目的核心资产是可追溯证据链，不是早期框架数量。
